MotionCaddie — end-to-end implementation guide

A single-POV golf swing becomes 3D biomechanics and a plain-English read. This guide covers the runtime flow, the full-app data model (every table + object-storage layout), the AWS resource inventory, and a rigorous gap analysis — what the shipped stateless demo has versus what the multi-user app still needs. Two postures throughout: live · demo is what runs today; planned is the full app.

Resources · A

Data model — every table the app needs

Aurora Serverless v2 (PostgreSQL). Three layers: reference data (seeded, versioned, read-mostly), core app data (per-user, transactional), and object storage (S3, keyed from the rows). Column types are Postgres; ▸ pk primary key, ▸ fk foreign key, ▸ enum constrained set. Field names below match the live JSON so the loaders map 1:1.

Schema is authored + validated. deploy/db/migrations/0001_init.sql (13 tables + the results_history view) and deploy/db/load_data.py (seed + backfill) exist. Dry-run against the repo JSON parses clean and produces 400 clips → 6000 indicator rows / 3200 event rows / 400 analyses, plus 15 indicators + 8 glossary terms. Still a gap: a live Aurora instance to apply it to, and the Cognito-driven users/consents path.

Resources · D

Gap analysis & open decisions

What stands between the shipped stateless demo and the full app, most-blocking first. Green = the recommended call.

P0 · infra authored, needs deploy

Live upload / processing path

IaC written + cfn-lint clean (deploy/infra/full_app.yaml): SQS→CPU-Lambda async processing, Aurora, S3, Cognito, alarms, budget. Verdict: no GPU needed — CPU Lambda handles a swing in 30–60 s at ~$0.01. Optional ml.g4dn.xlarge SageMaker Async (min-0) is gated behind EnableGpuWorker. Remaining: build the processing container + deploy.

P0 · schema done, needs infra

Database

Schema + seed + backfill are authored & dry-run-validated (deploy/db/). Remaining: provision the instance. Rec: Aurora Serverless v2 Postgres — relational fits the ERD; scales to 0.5 ACU idle; then psql -f 0001_init.sql + load_data.py --all.

P0 · blocker

No auth / identity

Demo is an open allow-list. Real users + per-user history + consent need Cognito. The diagram's "consent" step has no store today → the consents table.

P0 · cheap fix

Stale lifter in the deploy doc

AWS_DEPLOY_HANDOFF.md still bakes the motionbert_full cache + references. Post-swap it must bake golfpose3d + the retrained detector. One-line change; do before the next deploy.

P1 · quality

No upload validation gate

Single-person / view / fps-slow-mo checks before GPU spend. A bad clip should fail in ingest (cents) not after a GPU job (dollars).

P1 · compliance

Consent → retention not enforced

Raw video is PII (faces). Needs S3 lifecycle tied to consents.revoked_at and a delete-my-data path.

P1 · science

Optimization loop is manual

The unique(swing_id, pipeline_version) key makes re-analysis cheap, but nothing triggers it. Needs a backfill job on pipeline bump + the results_history Δ view.

P2 · resolved (pending apply)

Reference data as files

Bands / confidence / KB now have a loader into the seeded tables (load_data.py seed, units normalized, joints derived). Once it runs against a live DB, JSON becomes the seed source of record, not the runtime source.

What shipped this cycle

3D lifter MotionBERT → golf-fine-tuned MixSTE; One-Euro smoothing on the measurement branch; event detector retrained on MixSTE 3D (PCE@5 holds at 0.865).

Two branches, one lift

Events read raw 3D — they're motion reversals and need the sharp velocity signal. Measurements read smoothed 3D — angles are steadier when jitter is removed.

Honest scope

Austin's z-depth MLP was benchmarked and not adopted — it corrects only the height axis. MotionBERT still tops the PCE leaderboard and stays a selectable --lifter, but with the UE5 handoff retired it now feeds no deliverable.

The 3D replay is browser-native

The player's replay is a self-contained Three.js viewer (preview_3d.html) built from the same 3D — no game engine, no plugin. Retiring Unreal changed nothing the player sees.

Why serverless serves cache

The heavy pipeline needs a GPU. The demo doesn't run it — it serves precomputed 3D + scorecard from S3 and spends compute only on the Claude call.
